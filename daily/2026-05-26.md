## 📖 今日学习目标

理解 **上下文（Context）** 在 LLM 中的含义——为什么模型"记不住"、上下文窗口的限制、以及如何在 AI × Web3 场景中管理和利用上下文。

### 核心知识点

| # | 概念 | 一句话 |
|---|------|--------|
| 1 | 上下文窗口 | 模型一次能"看到"的最大 token 数（如 GPT-4 8K/32K，Claude 100K/200K） |
| 2 | Token 计数 | 输入 + 输出不能超过窗口上限，中文约 1.5-2 tokens/字 |
| 3 | 上下文管理与压缩 | 太长会截断、太短会丢失信息，需要裁剪/摘要/检索 |
| 4 | 检索增强（RAG 铺垫） | 从外部数据库取相关片段注入上下文，解决窗口限制 |
| 5 | 链式上下文 | 多轮对话中，历史消息也占用上下文——要管理"遗忘"策略 |

## 🛠️ 最小实践：测量上下文

**练习目标**：写一个 Python 脚本，用 tiktoken 计算一段文本的 token 数，模拟上下文窗口填充。

```
输入：一段文本 → tiktoken 编码 → 输出 token 数和预估窗口占用
```

用到：
- `pip install tiktoken`
- 选择模型编码（如 `cl100k_base` 或 `o200k_base`）
- 测试中英文混合场景

---

## 🔗 AI × Web3 关联

在 Agent 场景下上下文尤其关键：
- Agent 需要同时承载**用户意图 + 工具描述 + 链上数据 + 历史记录**
- 一条复杂交易的数据、合约代码、账户历史可能迅速撑满上下文
- **上下文压缩和 RAG 是 Agent 的必修课**
